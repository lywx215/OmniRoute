# Gemini 每个 Key 的每日模型请求限制实施方案

为 Google AI Studio 免费项目增加可配置的每日请求控制。当前使用场景是 12 个独立项目，每个项目一个 Key。文字 Flash 的每个具体模型每天允许 20 次，Flash Lite 的每个具体模型每天允许 500 次；某个 Key 的一个模型用满后，自动选择仍有额度的其他 Key。每日额度在太平洋时间午夜恢复。

基准为 2026 年 10 月 11 日获取的 `origin/main`，提交 `918d4f3019`。实现位于独立分支 `feat/gemini-daily-quota`。

## 配额范围与配置

Google 的限制按项目应用，RPD 在太平洋时间午夜重置，具体额度因模型而异。本方案按用户要求采用 20 和 500，作为 OmniRoute 本地额度，不能将这两个数当作所有 Google 项目的固定官方额度。[Google 速率限制文档](https://ai.google.dev/gemini-api/docs/rate-limits?hl=zh-CN)

配置保存在连接的 `providerSpecificData.geminiDailyQuota`：

```json
{
  "enabled": true,
  "flashRpd": 20,
  "flashLiteRpd": 500,
  "disableMinuteLimits": true
}
```

未配置的连接默认关闭，防止对其他付费项目自动套用免费额度。连接编辑窗口可启用或调整正整数额度；Gemini 页面提供批量应用入口，为当前所有 Gemini 连接写入上述完整配置。管理 API 使用已有的连接更新入口，并校验配置类型与范围。

按实际发往上游的模型 ID 建立计数桶，移除传输前缀，保留版本和预览版 ID。先识别 Flash Lite，再识别 Flash。图片生成、TTS、Live、音频、Pro 和 embedding 模型不套用这两组文字模型额度。别名与请求参数重写后的实际模型参与计数。

## 持久化与计数语义

SQLite 新增 `gemini_daily_request_counts` 表，唯一键为连接 ID、模型 ID、太平洋日期，保存请求数与更新时间。表关联连接，删除连接时删除对应计数；不保存原始 Key。数据库访问集中在 `src/lib/db/geminiDailyQuota.ts`，迁移使用 `206_gemini_daily_quota.sql`。

在真正启动 Google 请求前，用单条带上限条件的 UPSERT 原子占用一次额度。并发请求无法同时取得最后一个名额，多进程共享同一 SQLite 数据库时也适用。URL 与身份校验、取消检查先执行，占位与启动 transport 之间不插入异步等待。

每次上游尝试计一次，包括参数修复重发、网络错误与非成功响应。已经尝试发送的请求不退还次数，以避免无法判断 Google 是否收到请求时重复利用额度。缓存命中、模型列表查询、Key 验证及发送前取消不计数。

计数在普通重启后保留。数据库结构修复需要保留该计数表。旧日期记录不参与今天的限额，恢复通过切换日期完成，不依赖后台清零任务。

## 选择 Key 与额度耗尽

账号选择阶段查询当前模型的每日状态，只跳过该模型已耗尽的连接。连接的其他模型继续按自己的额度参与选择。会话黏性不能使耗尽连接绕过检查。如果请求参数规则可能改写模型，选择阶段暂不据此排除 Key，由最终生成 URL 的原子检查裁定，避免 Flash 已满却误拦仍有额度的 Flash Lite。

选择阶段的查询用于避免无效选择，实际发送前仍需原子占位。如果并发请求先耗尽该 Key，发送阶段抛出可信的本地每日额度异常。处理器将当前连接加入本次请求的排除集合，清除指向它的会话黏性，然后尝试其他允许使用的 Key。

每日额度耗尽不调用普通连接故障冷却，不计入整个提供商的熔断，不学习成 RPM 或 TPM 限制。组合路由同样将可信的本地每日耗尽归类为额度耗尽，直接推进下一目标，不写入模型故障锁定或轮询冷却。明确固定连接或管理租约的请求遵守固定范围，返回 429，不能偷偷切换到范围外的 Key。

所有允许的 Key 都耗尽时，返回 429 与 `Retry-After`，说明该模型的每日额度已用完及恢复时间。真实 Google 429 仍依据上游配额指标与重试提示处理；不能依靠旧的跨 Key 内存计数把一个项目的失败误判为所有项目耗尽。

## 太平洋时间恢复

使用 IANA 时区 `America/Los_Angeles` 生成计数日期，复用现有 `nextDailyResetAtMs` 计算下次午夜。冬季和夏季偏移、23 小时和 25 小时的切换日均由时区规则处理。午夜之后读取与占位自动进入新日期，界面同步显示新日额度和新的恢复时间。

## 每日模式中的 RPM 与 TPM

当 `enabled` 与 `disableMinuteLimits` 都为 true 时，跳过 OmniRoute 的 RPM reservoir、请求最小间隔、提供商分钟节流、Gemini 静态 TPM 预检查，以及 Combo 的连接 TPM 预算预检查。保留请求超时、队列取消，以及全局、提供商、连接和模型的并发控制。绕过 Bottleneck 节流时，将它原先承担的连接并发上限交给已有并发 gate，避免并发上限随之失效。

该设置只能控制 OmniRoute 本地限制。Google 自身的 RPM、TPM 和其他配额继续生效；收到真实上游 429 时仍需按上游信息切换或等待。

## 显示与管理入口

连接列表显示每日控制是否开启、Flash 与 Flash Lite 的配置，以及今天实际调用过的每个模型的已用次数、上限和剩余次数。未请求过的模型显示说明，不伪造 Google 剩余额度。用满的模型显示耗尽状态和下次重置时间。

管理 API 的连接列表附加 `geminiDailyQuotaStatus` 投影，配置仍保存在 PSD，运行计数单独存表，编辑配置不会覆盖计数。Gemini 页面可见且启用每日控制时，轻量轮询连接状态；隐藏页面暂停轮询。保存或批量应用后立即刷新。

## 验收条件

| 场景                                     | 预期                                   |
| ---------------------------------------- | -------------------------------------- |
| 同一个 Key 的 Flash 模型达到 20 次       | 第 21 次不发送，选择另一个 Key         |
| 同一个 Key 的 Flash Lite 模型达到 500 次 | 第 501 次不发送，选择另一个 Key        |
| Key A 用满某模型                         | Key B 及 Key A 的其他模型可继续调用    |
| 多个请求争抢最后一次                     | 仅一个请求占位成功                     |
| 内部修复重试或网络错误                   | 每次实际发送尝试计一次                 |
| 缓存命中、验证 Key、发送前取消           | 不增加每日计数                         |
| 服务重启与数据库结构修复                 | 今日计数保留                           |
| 太平洋午夜及夏令时切换                   | 新日计数恢复，重置时间正确             |
| 所有允许的 Key 耗尽                      | 返回 429 与午夜恢复提示                |
| 固定 Key 或管理租约耗尽                  | 返回 429，不越过固定范围               |
| 每日模式开启且 RPM 或 TPM 已配置         | 本地分钟限制不阻挡请求，并发上限仍生效 |
| 每日模式关闭                             | 保持连接原有行为                       |
| 界面编辑与批量应用                       | 配置校验正确，每模型计数和恢复时间更新 |

先执行新增模块与直接受影响模块的测试，再执行格式、lint、核心类型检查、Dashboard 类型检查、相关静态检查及文档检查。测试使用本地数据库和模拟 transport，不消耗用户的 Google 请求额度。

## 上线与回退

实现验证已通过每日计数、真实请求链路、组合路由、管理 API、UI 与并发控制的 53 项功能测试，以及相关既有回归测试。全仓 lint、核心类型检查、文件大小检查、循环依赖基线、翻译完整性与 ICU 检查通过；Dashboard 类型检查相对冻结基线没有新增错误。文档各子检查通过，其中 Windows 不支持的 grep 扫描使用 rg 收集同一变量集合后调用原校验器。

本机 `build:fast` 尚未完成：SWC 原生模块在加载 Next.js 配置时拒绝缓存目录的 Windows ACL，尚未进入应用编译。该环境限制需在可构建的环境中完成构建确认后再上线。

代码与测试完成后才能部署到 `https://omniroute.zeabur.app`。部署需要用户明确指示；本次实现本身不等于已部署。上线后为目标 12 个连接批量启用 20／500 的每日模式，并读取管理 API 确认每个连接的配置与计数投影。

新增计数从启用后的请求开始。当天上线前已经使用的 Google 额度及其他程序直接调用的用量无法自动补入；如果 Google 提前返回额度耗尽，应遵守真实上游响应。今后如果一个项目使用多个 Key，不能把它们当作相互独立的 Google 配额。

回退可以关闭连接的每日控制开关，恢复原有路由行为。配置变更和开关切换不删除已计次数，重新启用时仍能读到当天计数。数据库表可保留，以免回退或再次启用造成历史丢失。
